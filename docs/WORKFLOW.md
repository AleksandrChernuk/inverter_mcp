# Реальный маршрут конструктора (ВКР 7,1 из ВКР 6,3) → тулзы MCP

Записано со слов конструктора (пример ВКР №7,1, базовая комплектация, простой вентилятор).
Это эталонный сквозной процесс, который MCP должен ускорять. Не всё автоматизируется одинаково —
колонка «Реализуемость» честно это разделяет.

## Структура реального изделия (подтверждена по папке ВКР №7,1)
`.ipj` (проект Inventor), top `…00.00.000 СК Вентилятор.iam/.idw/.pdf/.stp`, узлы
`01.01.000 Робоче колесо`, `02.01.000 Дифузор`, `07.00.000 Ковпак`, `00.03.000 Рама`,
папки `Библиотека` (покупные/крепёж), `OldVersions`, `!Архів`, `Специфікація.xlsx`.
Итого ~56 .ipt, ~45 .idw, ~16 dxf, ~23 pdf. Кодировка: `ВКР 7,1 УЗ.ДЕ.ПОЗ Название`.

## Шаги процесса и покрытие тулзами
| # | Шаг конструктора | Тулза / подход | Реализуемость |
|---|---|---|---|
| 1 | Взять базу (ВКР 6,3) и сделать **Pack and Go** — не рисовать с нуля | `vent_new_product` (клон папки + `.ipj`) → **на Windows: Pack-and-Go + активация нового `.ipj`** | Авто (клон) + доводка Pack-and-Go |
| 2 | Переименовать все файлы по кодировке (в проводнике **и** в свойствах документа) | новый тул `vent_recode_product` (rename файлов + `Set iProperty` designation) | **Добавить тул** |
| 3 | Проверить размеры, начать подгонку **с рабочего колеса** (типоразмер) | `open_product` → `set_parameter` → `check_part` | Авто |
| 4 | Подогнать остальные по пропорциям; менять **толщину/тип металла** (рама, дифузор, обребровка, разболтовка) | `set_parameter` (в т.ч. sheet-metal thickness) + `set_material` (база) | Авто (при параметрич. моделях) |
| 5 | Собрать узлы → основная сборка (сначала без метизов) | `open_product` (узлы/сборка); правки параметров | Ассист |
| 6 | Проверить отверстия под двигатель, зазоры, что ничего не мешает | `check_interference` / `measure_min_distance` (база assembly_query) | Авто (проверки) |
| 7 | Файлы с плохой геометрией — перемоделировать с нуля | ручной CAD + базовые sketch/feature тулзы | Ручной |
| 8 | Прикрепить метизы | assembly place/constraints (база) или ручной | Ассист |
| 9 | **Чертежи** (самое долгое): деталировка узлов, сборочные, размеры, техтребования, выносные/вырезки | `make_gabarit` (скелет) + Drawing API; полная деталировка — длинный путь | Ассист → длинный roadmap |
| 10 | Спецификации в модели + правки «хвостов»; позиции на чертеже | `bom_report` + проверка соответствия; позиции — Drawing API | Ассист |
| 11 | Экспорт **PDF** чертежей по правильной кодировке | новый тул `vent_batch_pdf` (Drawing PDF по узлам + именование) | **Добавить тул** |
| 12 | Экспорт **DXF** для лазера с правильной иерархией/кодировкой | `vent_batch_flat_dxf` (+ именование по коду) | Авто (доводка имён) |
| 13 | Габаритное (монтажное) → сборочное всего изделия с покупными/узлами/техчастью | `make_gabarit` → сборочное — длинный roadmap | Ассист → длинный |
| 14 | Проверка спецификации и кодировки; проверка папок изделия | `bom_report` + `vent_check_product` (новый: коды, папки, соответствие) | **Добавить тул** |
| 15 | Выгрузка спецификации в **Excel** по правилам учёта металла | `bom_report`/`dxf_tools` → писатель XLSX (шаблон из `Специфікація.xlsx`) | **Добавить тул** |
| 16 | Отписаться в чат «цех-конструктора» (сначала на проверку гл. конструктору) | в kvz-ai: результат в чат + approval-gate | kvz-ai (Фаза 2) |

## Выводы для дорожной карты
- **Pack and Go — это официальный метод.** Мой `vent_new_product` (клон папки) верен, потому что
  Pack-and-Go делает папку самодостаточной со своим `.ipj` (ссылки относительные). Нужно: копировать
  `.ipj` и **активировать новый проект** в Inventor; на Windows проверю, нужен ли полноценный Pack-and-Go
  (ReferenceManager) вместо простого копирования.
- **Кодировка/переименование** — отдельный тул `vent_recode_product` (файлы + iProperties). Важный, частый.
- **Excel-спецификация по правилам учёта металла** — отдельный писатель по шаблону `Специфікація.xlsx`
  (можно на кросс-платформенной стороне поверх `bom_report`/`dxf_tools`).
- **Чертежи** — самая долгая и наименее автоматизируемая часть; идём от габаритки к деталировке поэтапно.
- **Проверки** (отверстия под двигатель, зазоры, соответствие спецификации, корректность кодов/папок) —
  высокоценный и реализуемый слой; собрать в `vent_check_product`.
