# AGENTS.md — dxf_tools/

Кросс-платформенный слой: анализ готовых DXF без Inventor (Python + ezdxf). Работает на Mac/Windows.

## Файлы
- `analyze.py` — разбор одного DXF: `parse_name` (толщина/материал/кол-во/обозначение — ДВЕ схемы
  имён), геометрия (габарит, длина реза, площадь, отверстия), проверки перед резкой. Возвращает dict/JSON.
- `batch.py` — обход каталога, сводная спецификация в `spec.csv` + список проблемных деталей.
- `compare.py` — регрессионный тест: сравнить свежий DXF (выгрузка из .ipt на Windows) с эталонным
  DXF из каталога. Габарит/площадь/рез/отверстия в допуске → вердикт PASS/DIFF, код возврата 0/1.
  `compare.py ЭТАЛОН.dxf НОВЫЙ.dxf --tol-mm 0.5 [--json]`.
- `spec_xlsx.py` — спецификация в XLSX по правилам учёта металла КВЗ (формат из реального
  Специфікація.xlsx: код склада `/*NNNNNN`, итог массы, +1% сварочной проволоки). `write_spec(rows,out)`
  или `--from-dxf DIR`. Проверено: воспроизводит эталон ВКР 7,1 (итог 101.66 кг).
- `materials.json` — справочник материал→код склада + плотность. Пополняйте при новых материалах.
- `requirements.txt` — `ezdxf>=1.4`, `openpyxl>=3.1`.

## Запуск
```bash
python3 -m venv venv && ./venv/bin/pip install -r requirements.txt
./venv/bin/python analyze.py "деталь.dxf"
./venv/bin/python batch.py "каталог"
```

## Правила
- Эта логика проверок — эталон для `vent_check_part` (C#). Меняешь правило тут — отрази и там.
- Единицы: DXF в мм (INSUNITS=4). Не хардкодь — читай из файла.
- Материалы для `parse_name` держи в списке `MATS` (ст09Г2С, 09Г2С, Ст3, Zn, …).
